## 1. 方法定位

产品卖点分析报告不是文案仓库，也不是写给下游 AI 的操作手册。它首先帮助负责人完成四次决策：

1. 第一次分析：现在最值得打什么卖点；
2. 上线前：哪些事实能说、哪些证据必须先补；
3. 执行后：结果支持继续、调整、换方向还是停止；
4. 新证据出现时：哪些判断应进入下一版本。

```text
产品事实与当前能力
+ 用户任务与购买机制
→ 声明底稿与候选方向
→ 资格闸门与一个核心主轴
→ 产品卖点分析报告 v1
→ 下游内容或销售执行
→ 证据记录与决策
→ 产品卖点分析报告 v2
```

有效卖点必须同时回答：产品真实具备什么、哪类用户为何在意、在什么场景产生价值、为什么值得优先选择、企业现在用什么证明和兑现。

## 2. 输入与来源优先级

### 产品输入

至少包含产品名称、SKU、规格、价格、渠道、当前阶段、真实能力、原料或工艺、使用或交付方式、证明材料和禁用边界。

来源优先级：当前正式产品资料与真实记录 > 明确的用户补充 > 历史宣传语。宣传语不能反向证明自己。

SKU 名称中的产地、年份、工艺只能确认“这是当前命名或标称”，不能自动证明标称真实。把名称事实与属性事实拆成不同声明。

### 用户输入

优先读取行为型核心用户、任务、场景、购买触发、痛痒爽点、替代方案、价格态度、购买阻力、信任证据、真实用户原话、AI 推断语言、整体置信度和待验证方向。

上游价值方向不是产品事实；产品功能也不自动等于用户在意的卖点。

### 证据修正输入

先在已授权的产品卖点报告目录中识别同产品最新旧版。候选排序依次使用：不晚于任务时间且最近的 `created_at` 或文件名日期；同日最大的 `version` 或文件名 `vN`；只有日期和版本全部缺失时才使用 `mtime`。只读取最终选中的一份旧报告正文，其余候选不得进入分析上下文。

除选中的上一版报告外，至少记录新增证据原文、时间、来源、受众、渠道、价格、优惠、内容和其他可能干扰判断的变量。没有测试条件时，只能记录新信息，不能轻易归因卖点效果。没有找到旧版才从头分析；找到旧版但没有新增证据时，保留原结论与状态，不伪造变化。

## 3. 三重事实闸门

凡是会影响核心卖点、支撑卖点、SKU 推荐、FAQ、行动计划或下游内容的结论，都建立独立声明并分配 `C001`、`C002`……。

### 证据状态

| 状态 | 含义 |
|---|---|
| `confirmed` | 可追溯证据直接支持 |
| `inferred` | 根据现有信息推断 |
| `unknown` | 缺少信息 |
| `conflict` | 来源互相矛盾 |

### 当前可用性

| 状态 | 含义 |
|---|---|
| `existing` | 当前已经存在并可兑现 |
| `planned` | 已计划但尚未交付 |
| `absent` | 当前明确不存在 |
| `unknown` | 无法确认 |

### 使用权限

| 状态 | 含义 |
|---|---|
| `direct` | 可在限定语境中直接使用 |
| `test_only` | 只可内部讨论或小范围测试 |
| `prohibited` | 不得对外使用或确定性回答 |

唯一直接使用规则：

```text
confirmed + existing + direct
→ 才能进入 direct_claim_ids
```

任何计划能力都不能通过当前能力闸门。任何推断、未知或冲突都不能因为表达顺畅而升级。

## 4. 候选生成与筛选

至少生成五个有实质差异的方向，来源可以是产品能力、使用体验、结果价值、场景适配、信任降低、选择降低、情绪关系价值和商业角色。企业收益不能冒充用户价值。

同义方向必须合并。品质好、匠心、专业、可靠、高端等空泛词不能充数。

每个候选先回答四个问题：

1. 当前产品能不能兑现；
2. 用户是否真的有关联；
3. 现在有没有证明路径；
4. 表达是否越界。

`planned`、`absent`、`unknown` 不能通过正式能力闸门。未来拟制作的教程、溯源页或检测材料不能作为现有证明。

对通过或可测试的候选用高/中/低评价：用户相关性、差异程度、可信程度、记忆传播性和购买推动力。每项写证据理由，不计算伪精确总分。没有竞品资料时，差异程度写“待验证”，不能宣称竞品空缺。

## 5. 核心主轴与买点转换

核心主轴只有一个。二至三个支撑卖点只能解释主轴如何实现、提供证明或降低阻力。不能说明自己支持主轴哪一部分的，应删除或另建任务。

如果没有方向通过，明确写“当前不能形成正式核心卖点”，并指定第一优先待验证方向，不勉强定稿。

按顺序转换，不跳步：

```text
产品事实或能力
→ 使用体验
→ 直接利益
→ 具体场景
→ 理想结果
→ 情绪或关系价值
→ 所需证明
```

规格和价格只证明规格和价格，不能自动证明入门、日常、进阶或送礼角色。SKU 角色如果来自推断，保持 `inferred + test_only`，直到有产品策略或用户行为证据支持。

## 6. 人类决策报告

报告开头先解释：这不是最终广告文案，而是卖点决策与迭代报告；用户应先按前六问执行，再把新增证据与上一版报告交回本 Skill 生成下一版本。

前六问负责当前判断：

1. 这款产品现在最应该卖什么？
2. 谁最可能为它买单，为什么？
3. 产品凭什么让用户相信？
4. 不同 SKU 分别适合谁，应该怎么选？
5. 用户最可能犹豫什么，我们现在能回答到哪？
6. 销售和内容现在能说什么、不能说什么？

第七、八问负责行动闭环：

7. 现在还缺哪些证据，应该先补哪一项？
8. 这轮卖点打完后，下一步应该继续、调整还是换方向？

每节遵循“直接答案 → 最少必要证据 → 限制或下一步”。正文使用 ✅、🟡、🔵、⚪、🔴 帮助浏览，不堆状态字典和机器字段。

## 7. 证据补充行动板

### 五类证据

| 类型 | 证明什么 | 不能替代什么 |
|---|---|---|
| `product_proof` | 产品事实、来源、规格、工艺是否成立 | 不证明用户在意或会购买 |
| `user_evidence` | 用户任务、阻力、语言和选择标准 | 不自动证明支付行为 |
| `behavior_evidence` | 咨询、购买、复购、退款或推荐行为 | 不自动解释行为原因 |
| `capability_delivery` | 教程、服务或交付是否已经存在 | 不证明能力能推动购买 |
| `compliance` | 某表达能否进入正式发布流程 | 不证明市场价值 |

每个会改变判断的证据缺口分配 `G001`、`G002`……，至少记录：

- 要回答的问题；
- 关联声明 ID；
- 证据类型和当前状态；
- 最低可接受证据；
- 收集行动和建议负责人；
- 完成标准；
- `blocking`、`decision` 或 `optimization` 优先级；
- 补齐后更新哪条声明、卖点、人群或 FAQ。

### 优先顺序

1. 先处理阻塞真实性、交付和合规的 `blocking` 缺口；
2. 再处理决定卖点或人群是否继续的 `decision` 缺口；
3. 最后处理表达、转化和放大效率的 `optimization` 缺口。

“取得材料”不是完整行动。行动必须说明材料由谁提供、什么形式算合格、拿到以后更新什么。

## 8. 卖点执行与版本迭代

### 定义本轮任务

每轮只验证一个主要卖点、一类优先人群、一个主要场景和一个希望用户完成的动作。说明哪些产品、价格、渠道、优惠和内容变量需要保持稳定。

### 记录执行结果

至少记录：测试时间、渠道、受众、实际表达、产品、价格、优惠、曝光、点击、咨询、下单、拒绝原因、真实原话、复购退款、推荐以及干扰变量。

点赞、打开和口头认可属于弱信号；主动索证、咨询、下单、复购、退款和推荐属于更强行为信号。强弱只说明证据接近购买的程度，不等于固定数字阈值。

### 决策闸门

| 结果 | 决策 | 处理 |
|---|---|---|
| 产品不能兑现或证明不成立 | `stop` | 停止使用该卖点 |
| 有证明但目标用户不在意 | `switch` | 更换卖点或人群 |
| 有咨询但购买不足 | `adjust` | 检查表达、价格、产品方案、信任和成交路径 |
| 行为证据方向一致 | `continue` | 扩大验证范围，不立即宣称完全验证 |
| 能力已交付但行为无变化 | `adjust` | 只更新可用性，不升级用户价值 |

### 生成下一版本

出现新证明、用户假设被支持或反对、完成一轮测试、产品或渠道变化、核心方向需要调整时，触发下一版本。

下一版必须回答：新增了什么证据、哪些旧判断被支持或反对、哪些状态变化、主轴是否继续、下一轮只验证什么。旧报告保留，不能从零重写后丢失判断变化。

## 9. FAQ、SKU 与风险边界

FAQ 的“现在可以确认”只能引用 `direct_claim_ids`，并只回答证据实际支持的范围。

- 没有产地证明：回答“当前没有可引用的产地证明”，不能说“可提供产地证明（待补）”；
- 教程未交付：回答“当前不能承诺附带教程”，不能说“配完整教程（待制作）”；
- 规格价格已知：只能解释规格价格，不能用未知的产地、年份、工艺为价格辩护。

SKU 表把“商品标称”和“已确认事实”分开。名称包含“8年、九制、九华山”时，只能在标称列原样记录；证明缺失时不能写进已确认属性列。

涉及酒类至少执行：不声称饮酒有利健康、改善身体、治疗、预防或产生确定保健效果；不从低度、口感或配料推导无负担、不伤身；没有材料时不确认产地、年份、无硫熏、古法、零添加或认证；不使用未经证明的第一、唯一、最好、百分之百或保证。

## 10. 证据修正与常见错误

新增证据后逐项标记：支持、反对、未知、冲突或测试干扰。保留原声明 ID；只有声明含义发生变化时才新建 ID。没有真实行为证据时不得升级为 `validated`。

常见错误：

- 把未来计划、待制作教程或拟新增服务写成当前能力；
- 把规格价格或 SKU 标称扩写成已确认角色和属性；
- FAQ 承诺尚不存在的教程、证明、溯源页或服务；
- 把产品证明当成用户价值证明；
- 把教程上线当成教程卖点已验证；
- 只记录点赞和阅读，不记录咨询、下单、拒绝和干扰变量；
- 完成一轮投放后不知道什么条件触发下一版本；
- 新版本从零重写，丢失上一版被支持和被反对的判断；
- 人类正文堆满字段、技术规则和 AI 指令；
- 把报告扩成项目管理、平台文案、销售话术、竞品研究或合规报告；
- 保存前不预览确认，或覆盖旧版本。
