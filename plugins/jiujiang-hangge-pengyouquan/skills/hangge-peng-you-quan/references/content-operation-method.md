## 1. 运行模式

### 周内容运营

用于一周、下周、连续多天、每天多条、排期或系列内容。默认每天 3 条、7 天 21 条，允许用户修改日期、天数和数量。

### 单条创作

用于一个真实事件、观点、问题、产品或素材。选择能把任务讲清楚的最短长度，默认只给一个成稿。

### 改写与审核

用于检查或重写已有朋友圈。输出发布状态、主要问题、对应规则和修改后正文。

## 2. 资料资格

每个候选素材记录：

```text
来源：
日期：
原始事实或原话：
状态：已发生／进行中／未来计划／个人观点／上游判断
是否可公开：
可支持的结论范围：
产品或合规风险：
```

来源存在不等于结论成立：

- 用户假设只支持内容角度，不是客户事实；
- 卖点报告中的候选判断不能覆盖产品正式资料；
- 表达样本只支持口吻；
- 一张晒单图不自动证明口感、效果或复购；
- 历史活动不自动代表本周仍有效。

## 3. 周规划

### 3.1 确定范围

- “本周”指当前自然周；
- “下周”指下一自然周；
- “规划一周”未给日期时，从次日开始连续 7 天；
- 用户指定日期、天数和数量时优先使用；
- 在成果文件中写明日期范围和总量。

### 3.2 判断本周经营阶段

从用户指令、经营周报和活动资料判断：

- 日常关系维护；
- 产品或内容预热；
- 销售期；
- 活动冲刺；
- 会员运营；
- 售后与复购。

无法判断且会改变内容比例时，只问一个最高影响问题。用户没有提供时，不根据目录为空推断“本周没有活动”。

### 3.3 分配经营目的

使用五类：

- 专业信任；
- 产品种草与案例；
- 关系互动；
- 真人生活；
- 行动转化。

先按业务阶段提出数量，再检查：

- 总数等于用户要求；
- 销售内容不过密；
- 没有真实案例时不分配案例任务；
- 没有真实活动时不分配活动转化；
- 真人生活必须有真实素材锚点。

### 3.4 建立题材池

优先读取：

- 用户本次明确提供的主题和素材；
- 当前经营周报和活动资料；
- 产品库中的最新正式产品资料、用户假设和卖点报告；
- 用户案例、FAQ 和已授权反馈；
- 航哥本周真实行程和现场；
- 朋友圈分发库的历史内容。

题材池至少记录：

| 题材 | 经营价值 | 事实状态 | 来源 | 可用素材 | 风险 | 可承担目的 |
|---|---|---|---|---|---|---|

### 3.5 生成内部排期矩阵

| 日期时段 | 长度 | 题材 | 经营目的 | 内容角度 | 事实来源 | 配图状态 | 承接动作 | 发布状态 |
|---|---|---|---|---|---|---|---|---|

要求：

- 一条只标一个主要经营目的；
- 长短和内容轻重分散安排；
- 产品与转化内容前后穿插专业、互动或生活内容；
- 每个“可发布”位置至少有一个真实信息锚点；
- 可以规划 21 个位置，但不能无条件承诺 21 条可发布成稿。

这张宽表只用于内部规划和事实核对，不直接作为面向使用者的一周总览。正式周成果使用第 7 节的“一周内容日历”，把事实来源和审核信息移到文件末尾。

### 3.6 生成并检查正文

对每条执行：

```text
核对事实
→ 选择内容类型和长度
→ 读取相近表达样本
→ 应用对应正向规则
→ 写成航哥口吻
→ 执行负向拦截
→ 检查重复、事实、隐私和合规
→ 确定发布状态
```

## 4. 单条创作

1. 获取一件事、一个问题、一个观点或原始文字；
2. 判断事实状态和使用边界；
3. 确定主要经营目的与内容类型；
4. 选择最短必要长度；
5. 读取对应风格样本；
6. 生成正文、配图建议和承接；
7. 完成发布检查；
8. 直接保存成果文件。

只有缺少的信息会改变事实或核心角度时才追问一个问题。

## 5. 改写与审核

输出：

```markdown
## 审核结论

- 状态：
- 主要问题：
- 违反规则：
- 修改方向：

## 修改后文案

……
```

不要给机械分数。事实不足时不通过改写掩盖，标记待补事实。

## 6. 历史去重

历史范围只限运行配置指定的朋友圈分发库。

1. 先扫描 Markdown 文件名，识别周期、产品和主题；
2. 完整读取最近 30 天或最近 4 份周成果；
3. 针对候选产品、核心观点、场景、案例和 CTA，在全部历史中搜索关键词；
4. 只打开命中的相关文件，不把整个历史目录一次性装入上下文；
5. 检查主题、核心判断、开头、场景、案例、产品密度和 CTA 重复。

历史为空时正常继续，并在内部说明“暂无历史内容可供去重”。

## 7. 成果文件

### 周成果

```markdown
# 航哥一周朋友圈内容

## 一、本周执行摘要
## 二、一周朋友圈内容日历
## 三、本周经营目的分配
## 四、完整朋友圈文案
## 五、待确认与素材补充
## 六、内部来源与发布检查
```

#### 一、本周执行摘要

用短列表说明：

- 规划周期；
- 发布数量；
- 本周主题；
- 经营阶段；
- 核心目标；
- 可直接发布、待补素材、待人工确认和暂不可发布的数量。

不要在摘要里展开方法解释。

#### 二、一周朋友圈内容日历

默认每天 3 条时，使用四列表格：

```markdown
| 日期 | 早间 | 午间 | 晚间 |
|---|---|---|---|
| 7月24日 周五 | **01｜专业信任**<br>主题与核心角度<br>✅ 可直接发布 | **02｜产品种草**<br>主题与核心角度<br>✅ 可直接发布 | **03｜关系互动**<br>主题与核心角度<br>🟡 待补素材 |
```

要求：

- 以日期为行、发布时段为列；
- 每个单元格只放连续编号、主要经营目的、主题与核心角度、发布状态；
- 不把完整文案、事实来源、长配图说明或内部审核塞进日历；
- 日历编号与后续完整文案严格一一对应；
- 单元格保持短小，主题通常一至两行；
- 状态只使用：
  - `✅ 可直接发布`
  - `🟡 待补素材`
  - `🔵 待人工确认`
  - `⛔ 暂不可发布`

发布频率不是每天 3 条时：

- 每天数量一致且不超过 4 条：按实际建议时段增减列；
- 每天数量不一致或每天超过 4 条：改用紧凑的逐条总览表，避免生成难以阅读的超宽日历；
- 逐条总览表只保留 `编号｜日期／时段｜经营目的｜主题与核心角度｜发布状态`；
- 无论采用哪种表格，都必须覆盖全部计划位置并与完整文案编号对应。

#### 三、本周经营目的分配

```markdown
| 经营目的 | 数量 | 本周作用 |
|---|---:|---|
| 专业信任 |  |  |
| 产品种草与案例 |  |  |
| 关系互动 |  |  |
| 真人生活 |  |  |
| 行动转化 |  |  |
```

数量之和必须等于总发布量。没有使用的经营目的可以省略，不为填满表格虚构任务。

#### 四、完整朋友圈文案

先按日期分组，再按日历编号排列：

```markdown
### 第 1 天｜7月24日（周五）

#### 01｜早间｜专业信任｜中篇

**发布状态：✅ 可直接发布**

##### 朋友圈正文

……

##### 配图建议

……

##### 承接动作

……
```

待补素材或待人工确认的位置也保留编号，但不得伪造正文填满位置。直接说明缺口、需要补什么以及未补齐前的发布状态。

#### 五、待确认与素材补充

按编号列出缺口，例如：

```markdown
- 06：需要航哥本周真实生活、泡酒操作或聚会素材。
- 16：需要确认当前购买入口和库存状态。
```

没有待补项时写“本周无待补素材与确认项”，不要保留空标题。

#### 六、内部来源与发布检查

将面向内部的事实来源、风险和检查结果放在成果末尾，并用同一编号追溯：

```markdown
| 编号 | 主要事实来源 | 检查结果 |
|---|---|---|
| 01 |  | 通过／待确认／不可用 |
```

这里可以记录事实资格和限制，但不倾倒长篇内部推理。

### 单条成果

```markdown
# 航哥朋友圈｜主题

## 内容判断
## 可直接发布的文案
## 配图建议
## 后续承接
## 内部审核
```

成果文件以复制发布为主。方法教学、长篇推理和内部规则说明不进入正文。

## 8. 停止与回退

不创建成果文件：

- 找不到知识库根目录或输出目录；
- 缺少内置 Profile、Style、Business、表达样本或规则；
- 周规划缺少会改变整体分配的经营目标；
- 价格、活动、库存或会员权益冲突；
- 用户要求的案例、生活和转化内容主要依赖编造；
- 内容包含不能通过改写消除的健康、隐私或事实风险。

停止时在对话中只返回最小缺口。不要在分发库写入“假成果”或空模板。
